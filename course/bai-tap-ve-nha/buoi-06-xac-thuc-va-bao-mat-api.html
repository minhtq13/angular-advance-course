Phần 0 · Khởi động: viết ra giấy (4 phút)

  1. 401, 403, 409 trả lời ba câu hỏi gì? Frontend làm gì với mỗi loại?
  2. Server Care Portal kiểm tra những gì trong một access token?
  3. Refresh token rotation là gì? Gửi lại refresh token đã dùng thì server làm gì, vì sao?
  4. Vì sao N request cùng nhận 401 phải dùng chung một lần refresh?
Ôn lại sau khi đã viết xong
CâuÝ chính
1401: anh là ai (không/hết hạn/sai token) → refresh một lần, không được thì đăng nhập lại. 403: không đủ quyền → báo, không refresh, không đăng xuất. 409: dữ liệu đã đổi → báo, cho tải lại.
2Signature HS256 (thuật toán cố định), exp với clock skew tối đa 10 giây, iss, aud, token_use=access; quyền lấy từ roles rồi @PreAuthorize.
3Mỗi refresh token chỉ đổi được một lần, mỗi lần đổi ra token mới cùng family. Token đã dùng bị gửi lại → có thể đã lộ (hai bên cùng giữ) → revoke cả family.
4N refresh cùng một token: một cái thành công, N−1 cái bị coi là reuse → cả phiên bị revoke → người dùng bị đá ra dù không ai tấn công.

Phần 3 · Vận dụng: tải hóa đơn PDF (10 phút)

Tính năng mới: ở trang chi tiết thuê bao có danh sách hóa đơn, mỗi dòng có nút Tải PDF. Backend thêm GET /api/subscribers/{id}/invoices/{invoiceId}.pdf. Lập trình viên định viết <a [href]="apiUrl + '/api/subscribers/' + id + '/invoices/' + inv.id + '.pdf'" download>.

  1. Link này có tải được không? Vì sao (gợi ý: ai gắn header Authorization)?
  2. Đề xuất hai cách tải đúng, nêu ưu nhược điểm. Cách nào không được dùng: đặt token vào query string ?access_token=...? Vì sao?
  3. Viết 4 dòng cho ma trận kiểm thử bảo mật của API này (tình huống, vai trò, kỳ vọng). Ít nhất một dòng về quyền theo dữ liệu: hóa đơn invoiceId không thuộc thuê bao id.
Đáp án tham khảo (chỉ mở sau khi đã viết)
  1. Không. Trình duyệt tự tải link, không đi qua HttpClient nên interceptor không gắn Bearer → 401 (trình duyệt hiện trang lỗi hoặc file JSON lỗi).
  2. (a) HttpClient.get(url, { responseType: 'blob' }) qua interceptor, rồi URL.createObjectURL + thẻ a tạm để lưu; nhược: cả file nằm trong bộ nhớ, không có thanh tiến trình của trình duyệt. (b) API cấp link ký sẵn ngắn hạn (vài chục giây, chỉ cho đúng hóa đơn đó, dùng một lần); nhược: thêm một endpoint, phải làm đúng signature và hạn. Không đặt access token vào query string: lọt vào log server/proxy, lịch sử trình duyệt, header Referer, và token đó dùng được cho mọi API.
  3. Ví dụ: không token → 401; AGENT tải hóa đơn hợp lệ → 200, Content-Type: application/pdf; invoiceId của thuê bao khác ghép với id này → 404 (không lộ hóa đơn tồn tại) và không trả nội dung; hóa đơn không tồn tại → 404; (nếu dùng link ký sẵn) link hết hạn hoặc dùng lần hai → 403/410.
